Vamos bien, me gustó que hayas construido un middleware de manejo de errores, lo único sí es que tener un middleware por cada tipo de error será inmantenible, mejor, hagamos un mapa de tipos de errores http soportados en la carpeta config que luego también puieda importar las rutas. Ahora, Necesito que además del middleware de auth, tengamos uno de autorización, el mapa de roles/permisos tendremos solo dos permisos, uno llamado 'can get score'otro 'can get all score'. Es imporetante, porque cambia una definición. Dije antes qeu los permisos son a nivel de endpoint/tipo consulta, pero ahora es personalizado. Por defecto, el middleware de autorización debe tener un callback definido en el service del mismo recurso, el objetivo del service es solo validar si es que tiene permisos para acceder al recurso que se está solicitando. Hay recursos triviales, pero en este caso en particualr, el can get score permite ver el score del rut consultante, el can get all score puede ver el score de cualquier rut.
