Crearemos la spec 2, el repositorio es https://github.com/DavidSlva/financial-risk-manager, utilizaremos gitflow para su manejo. feature/spec-slug como nomenclatura de specs, main como producción, staging para certificacion y develop para desarrollo. La estructura de trabajo con agentes está basada en la creación de workspaces con su propia rama, nunca tendremos dos workspacews para la misma spec, pero sí podemos tener workspaces de integración de cambios. Cada commit de promoción debe ir con su tag, versionado incremental, x.y; donde x es el id de la spec e y actualizaciones sobre esa spec. Se le agrega el prefijo rc solo en pasos de develop a staging se le quita en los pasos a producción. La spec 2 define el cómo trabajaremos asi que debe inicializar el claude.md.
