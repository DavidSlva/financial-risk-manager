En cuanto a la seguridad, la autenticación está basada en JWT, simétrico, donde la key se genera mediante crypto con 64 bytes. Tendremos un servicio que se encargará de generar el access y refresh token. Donde el TTL del access se configura en el archivo de config, al igual que el de refresh. Ojo con algo, el refresh no autentica, solo refresca y puede ser revocado. Ahora sí necesito que usemos el método SDD, necesitamos pensar en el modelo de datos base del usaurio, la app es simple, no solo necesitamos devolver un scor financiero asociado a un rut, no tendremos persistencia en base de datos asi que usaremos un users.json y scores.json para almacenar los datos base de cada uno, aunque necesitamos validar la integridad referencial de ambos, orientado a SQL. No necesitamos hacer algo complejo. El usuario es necesario que solo tenga rut y rol, donde tenemos que tener un validador del formato de rut asi que dejemoslo como un punto pendiente derivado de esta spec. Me interesa que el JWT pueda ser revocado, por lo que necesitamos que el validador pueda reivsar la marca de vigencia del usuario. Para que luego en su lógica no permita generar uyn nuevo access con el refresh ni auitenticar con el access.

_Aclaraciones del usuario (preguntas de seguimiento):_

- La emisión del primer par de tokens (login / verificación de identidad) queda **fuera de alcance**, como punto pendiente derivado.
- En esta pasada se escriben specs, plan y tasks **sin implementar**; el usuario revisa y luego se implementa.
